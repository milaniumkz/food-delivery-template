# Инструкции для Codex

1. Прочитать README, docs/SPEC_RU.md, docs/IMPLEMENTATION.md и docs/KASPI.md до изменений.
2. Текущий репозиторий — starter. Не выдавать mock, статический макет или незавершённый модуль за production.
3. Реализовывать этапы из IMPLEMENTATION последовательно вертикальными сценариями. Заканчивать этап проверяемым PR с описанием реально пройденных проверок.
4. Все новые репозитории по требованию владельца должны быть публичными. Никогда не публиковать существующие приватные проекты целиком, конфигурации клиентов, историю чужих проектов, секреты, сертификаты и персональные данные.
5. Брендинг читать только из конфигурации; не добавлять название клиента, цвета и логотип непосредственно в экраны. Валюта KZT, цены — целое число тиынов.
6. Клиент не является источником истины для цены, скидки, статуса оплаты или роли. Пересчитывать на сервере.
7. Kaspi по умолчанию отключён. Только mock до аудита исходника, разрешения правообладателя и подтверждённых параметров провайдера. Не изобретать Kaspi endpoints, подписи или статусы.
8. Не выполнять реальные платежи, возвраты и публикацию в App Store/Google Play без отдельного поручения.
9. Выбрать и зафиксировать поддерживаемые версии SDK в этапе 0; добавлять lockfiles вместе с зависимостями. Не использовать latest в production.
10. Проверки: node --test apps/api/test/*.test.mjs; node tools/brand.mjs brands/demo/brand.json. После реализации платформ добавить lint/typecheck, интеграционные тесты Postgres, Flutter analyze/test и полный E2E.
11. Время хранить в UTC, бизнес-расписание с IANA zone. Логи без телефона, адреса, токенов и тела платежных уведомлений.
12. При ошибках внешнего подключения остановить только зависимую операцию и зафиксировать точный блокер. Не изменять другие проекты.
