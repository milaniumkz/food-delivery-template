## Что требуется для повторного использования
1. Получить точную ссылку/ветку/путь к платёжному модулю и действующую документацию продукта Kaspi.
2. Проверить владельца, лицензию, договорные ограничения и разрешение на публикацию. Владение аккаунтом GitHub не доказывает права на сторонний код.
3. Отделить чистую бизнес-логику от merchant IDs, сертификатов, токенов, URL окружений, логов и данных клиентов. Не переносить исходную историю.
4. Проверить аутентификацию уведомлений, статусы, идемпотентность, сверку сумм, refunds, timeout/retry, поздние платежи. QR или возврат из приложения сам по себе не подтверждает оплату.
5. Перенести допустимую логику за PaymentProvider и подтвердить sandbox тестами. Секреты — исключительно server-side secret storage.

Сейчас `KaspiPaymentProvider` намеренно бросает ошибку при создании. `MockPaymentProvider` только в памяти для тестов; у него нет HTTP endpoint и он не принимает внешних уведомлений. Это не полноценный backend и не эмуляция протокола Kaspi.
